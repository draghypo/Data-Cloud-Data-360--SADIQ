Data Model: - Data Model is a collection of entities, Attributes, Relationship and Cardinality. In any Database you have entities such as (Object or Table) Which contains Attributes such (Fields or column) These Attributes connected through relationship and each relationship has cardinality for ex: - An Account can have one or more contacts where one or more represent the cardinality.

Data Types in 360: - when you create a data stream Data 360 attempts to detect the data type of each field. Mapping DLO to DMO must be same. Note :- {After DLO created you can not changed the datatype of the fields}.

                                    Normalization VS DeNormalization
                                  -------------------------------------

Normalization: - Normalization break's down data into separate table or object, so piece of data is stored in only one place.                   Advantage- It improved data integrity reduces Data Redundancy can be very effiecient data model for datsets                              with repetaion in attibutes.
                  Drawback- It increases complexity in querying usually involve join in multiple table can impact                                         performance,harder to use natively outside for the system.

Denormalization: - Opposite of Normalization introduced redundancy by persisting data as column attributes instead of a                           related data.
                  Advantage- Denormalization improved query performance, querying a single table that contains all needed                                  values are usually faster and more efficient for heavy application.
                  Drawback- Denormalization Data Redundancy and maintenance is stored in multiple places can lead to increase                             data storage and risk of data inconsistency.
