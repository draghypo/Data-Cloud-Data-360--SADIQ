                            Some Different type of Data 360 objects
                          ----------------------------------------------

**DSO: -** It stands for Data Source Object initial entry point for any data stream coming into Salesforce Data Cloud.
            When we configure a Data Stream (from Amazon S3, Web/Mobile SDKs, Google Cloud Storage, or an API), Data Cloud 
            first creates a Data Source Object (DSO). It captures and hold the raw payload in its original, exact schema as               provided by the external system. API Suffix: Uses the __dso suffix (e.g., Shopify_Orders__dso).

**DLO: -** It stands for Data Lake object it is the physical, raw database table inside Data Cloud's underlying columnar data lake. While a DSO is the temporary staging definition, the DLO is where the imported data physically lives and persists.
* It stores raw data as-is from your Data Stream (whether imported from S3, Snowflake, Kafka, or an Ingestion API payload).   
* API Suffix: In code, API calls, and metadata, DLOs end with the __dlo suffix (e.g., Shopify_Orders__dlo, AWS_User_Logs__dlo).
* Immutability: DLOs retain source format fields. However, you can add Formula Fields at the DLO level to sanitize data (e.g., converting dates, concatenating string fields, trimming spaces) before mapping to a DMO.
* Primary Key Enforcement: Every DLO requires a designated Primary Key (or composite key) to ensure row uniqueness within the data lake.


**DMO: -** A DMO (Data Model Object) is the harmonized, semantic business object inside Data Cloud.While a DLO (__dlo) stores raw, messy source data (like an ERP table or S3 CSV), the DMO (__dlm) is the clean, standardized representation that conforms to the Customer 360 Data Model. It is the single most important object type for developers, admins, and AI agents.

  **Key Technical Aspects of a DMO**

* Harmonized Schema: A single DMO can receive data from multiple DLOs across different systems. For example, a Contact DLO from Salesforce CRM, a User DLO from Snowflake, and a Customer DLO from an ERP can all map their fields into one unified ssot__Individual__dlm DMO.
* API Suffix: In Apex, SOQL, and REST APIs, DMOs end with __dlm (e.g., ssot__Individual__dlm, ssot__SalesOrder__dlm, Custom_Vehicle__dlm).
* Standard vs. Custom:
Standard DMOs: Pre-built by Salesforce and prefixed with ssot__ (Single Source of Truth), such as ssot__Individual__dlm, ssot__Account__dlm, or ssot__ContactPointEmail__dlm.
Custom DMOs: Created by developers for domain-specific data models not covered by standard schema (e.g., Policy_Subscription__dlm).
* Target for Downstream Engine Features: Identity Resolution rules, Calculated Insights (CI), Segments, Data Cloud Triggered Flows, and Agentforce Grounding all operate directly on DMOs.
